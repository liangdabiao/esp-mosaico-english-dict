# 让实测行高而不是字号决定版式

记录于开发[英语词典应用](english-dict/README.zh_CN.md)期间。这个应用的每一处版式缺陷，
根源都是同一个习惯：按字号选区块高度，然后发现字体画出来比那个高。这篇写的是取代猜测的
那两套数字，以及由它们推出的算术。

## 行高不是字号，预算值也不是实测值

三档字号各有两个不同的数，把它们混起来就是 bug 本身：

| 档位 | 预算（`字号 x 1.3`） | 实测 `line_height` |
| --- | --- | --- |
| 16 px | 21 | **20** |
| 24 px | 31 | **29** |
| 32 px | 42 | **36** |

预算那一列是版式常量所依据的数；实测那一列直接从生成出来的
`assets/fonts/wd_font_*.c` 读出（`font->line_height`），它才是 LVGL 真正前进的高度。
**每一档的实测值都更小**，所以按预算值定的区块是保守的 —— 这正是这些常量敢于用整数写、
而不必先去设备上量的全部理由。

要紧的推论在反方向：区块必须按**预算**定，绝不能按观测值定，因为「它放得下」这条断言
得在没人回头翻字体文件的情况下依然成立。`WD_QUIZ_RESULT_H` 就是 `2 x 21 = 42 + 2 = 44`，
尽管两行真实只需要 `2 x 20 = 40`；那多出来的 2px 是余量，不是浪费。

## 「只差 1px」其实差的是整整一行

测验页曾经给题干区留了 **104** px，注释还写着「5 行 x 21 = 105，所以 104 只差一行」——
这句话错了两次。`104 // 21 = 4`：那个区块装得下四行、不是五行，第五行直接被裁掉。
在屏幕上，它表现为一句话说到一半就没了，看起来像内容问题，而不是版式问题。

这个数改成了 **105**，并把推理写进常量旁边。能拦住它的检查是算术，不是真机测试：

```
放得下的行数(h) = h // 预算行高(档位)
```

任何「要装 n 行」的区块高度都得 `>= n x 预算`，而「差一点到 n x 预算」就是 `n - 1`。

## 同一个陷阱藏在 `snprintf` 缓冲区里

缓冲区上的「差一点」是一模一样的形状。测验反馈行要画「答错」加单词加音标，词库里最长
单词 18 字符、最长音标 21 字符，再加两个汉字加一个空格是 5 个单位 —— 合计 45 个半角单位，
而一行只有 25 个单位，所以这一行**不可能**挤在一排里：

- 反馈区块从 28px（一行）长大到 **44px**（两行），那 16px 从四个测验选项盒里出，每个从
  34px 收到 30px；
- 两行是**显式**写进字符串的（带 `\n`），而不是交给标签自己折 —— 只有显式换行，
  版式才能被提前核对；
- 缓冲区按**最贵的调用方**定尺，即 `WD_UI_WORD_CAP + WD_UI_IPA_CAP + 8`，
  而不是按眼前这个值。

少了任何一半，缺陷都会以最坏的方式间歇出现：短词挤得下，长词悄悄丢掉整行音标，
看起来像随机 bug，而不是一个固定容量问题。

## 把每条预算在编译期绑到版式上

预算以具名常量住在 `main/wd_ui.h`，算式就写在旁边；`wd_ui.c` 用断言把关系钉死，
于是后来的改动会在**构建**上失败，而不是在设备上：

```c
_Static_assert(WD_QUIZ_CHOICE_H >= 30, "选项行这么矮会看不清选中条");
_Static_assert(WD_ZONE_STATUS_H + WD_QUIZ_QUESTION_H +
                   WD_QUIZ_CHOICE_H * WD_QUIZ_CHOICES + WD_QUIZ_RESULT_H +
                   WD_ZONE_HINT_H <= WD_SCREEN_H,
               "测验页放不下（22 + 105 + 4x30 + 44 + 28 = 319）");
```

列表页是同一种断言 —— `WD_ZONE_STATUS_H + 8 x WD_LIST_ROW_H + WD_ZONE_HINT_H <=
WD_SCREEN_H`，算出来是 `22 + 8 x 31 + 28 = 298`，320 里余 22px 真余量。这些宿主测试都
覆盖不到：常量会把 `lvgl.h` 拉进来。编译期断言是唯一零成本留在回路里的检查。

## 32px 档为什么不画汉字

还有一个「量而不是猜」的推论。32px 子集只有 **93** 个码点，**一个汉字都没有**
（见[字体回退链那篇](ipa-fallback-font-chain.zh_CN.md)）。所以中文标题**根本**不能用
32px 画 —— 那会是一排方框。于是 `WD_BOOT_TITLE_H` 是 **31**（24px 档的预算），不是 42，
注释也如实写着，因为「大字档总该放得下」正是那种一不小心就会溜回来的假设。
