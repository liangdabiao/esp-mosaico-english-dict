# 用一条回退链让每个音标都不画成方框

记录于开发[英语词典应用](english-dict/README.zh_CN.md)期间。词库几乎每条都带一行音标，
而这块板上所有应用所依赖的字族，凑不齐音标要用到的全部符号。这篇写：缺的是哪 18 个码点、
为什么「把两套字体合并成一套」是错的修法、以及运行期回退链是怎么接起来的。

## 缺口：18 个码点，而大部分词条都要用到其中三个

界面要画三档字号（16、24、32 px），一个单词可能落在任意一档。主字体是 Noto Sans CJK SC。
拿它跟应用**实际要画**的字符集比对，正好缺 **18** 个码点，全都是音标：

```
ŋ ɒ ɔ ə ɚ ɛ ɜ ɝ ɪ ʃ ʊ ʌ ʒ ʳ ˈ ˌ ː ˚
```

这些一点不冷门。`ə`、`ɪ`、`ɛ` 出现在 19,513 条词条的绝大多数里，`ˈ`（主重音）几乎每条都有。
所以「偶尔缺一个字」这种说法在这里站不住 —— **缺一个字形，整行音标就是一排方框**，
那比不显示还难看。

## 合并两套字体是错的修法，理由有点绕

想当然的做法是：把两套源合成一套字体 —— 从 Noto Sans 里切出音标字母，从 Noto Sans CJK 里
切出汉字，再把字形表合并。在这里行不通，而且失败的原因不是「覆盖率不够」：

- 两套字体给**同一个码点不同的 advance 宽度**。`i` 在一套里是比例字宽，在另一套里是等宽。
  合并必须为每个码点挑一个数，而无论挑哪个，对按另一套排版的文本都是错的。
- 合并还得为结果挑**一个 `line_height` 和一个 `base_line`**，而这两个在两套源里也不一样。
  整套版式预算正是从主字体的度量算出来的，合并后的字体把那个预算悄悄作废了。

逐个码点「择优」理论可行、维护上不可行：以后每加一个符号，都要把「谁的宽度说了算」这个问题
为全部 18 个符号重开一遍。

## 修法：只装缺的那些，运行期把两套串起来

`gen_font.py` 为每一档产出**两个**文件：

| 文件 | 内容 |
| --- | --- |
| `wd_font_<n>.c` | 从主字体画的完整字符集，去掉那 18 个缺失码点。 |
| `wd_ipa_<n>.c` | 恰恰就是那 18 个码点，从 Noto Sans 画。 |

补充字库故意做得很小 —— 18 个码点在 16、24、32 px 三档合计只有 8,704、12,509、18,508 字节 ——
因为它只会被问到「主表答不上来的字符」。`wd_font.c` 在初始化时把每一对连起来：

```c
s_font[tier] = wd_font_16;          /* 主表 */
s_font[tier]->fallback = &wd_ipa_16; /* 只在主表缺这个字形时才被问 */
```

**LVGL 的回退是按字形解析的，不是按字符串。** 在主字体上取 `ə` 的字形描述会返回空，
这时才去问回退表。没有「切换成音标字体」这种按字符串的模式，调用方也不必知道某条音标里
含不含那 18 个符号。反过来说，一条一个都没有用到的音标，回退这一步是零成本的。

相比合并，这套好在哪，说具体点：**没有任何字形被复制**，所以不存在宽度分歧；每个字形保留
它所属字体的度量；而主字体的 `line_height` —— 整套版式预算的源头 —— 一点没被动过。

## 缺失集合是推导出来的，不是维护出来的

那 18 个是生成期算出来的，不是手打的：

```
missing = （应用要画的字符集） - （主字体拥有的码点）
```

`gen_font.py` 向源字体的 `cmap` 要覆盖率再相减。于是：加一个含主字体恰好缺的符号的新词，
补充字库会自动变宽；把主字体换成已经全有这 18 个码点的一套，补充字库会自动缩到空，
都不用改代码。字符集本身来自 C 表生成器用的同一个内容模块，所以字体与词库不可能对
「需要画什么」有分歧。

## 门禁查什么

三项，都很便宜：

1. `gen_font.py --check` 按**当前源码**重算需要的集合，与已分发 `.c` 里**实际存在**的码点
   对比。`want - got` 就是失败信号 —— 于是新加的一句中文界面文案如果引入了子集里没有的
   码点，会在门禁这一步失败，而不是以方框的形式到设备上。
2. `wd_ui_init()` 在任一档连 ASCII 都取不到字形、**或回退链没接上**时返回 `false`。
   这是唯一允许让应用停下来的 UI 级失败：满屏方框比不启动更糟。
3. 应用能画的每个字形，在转换之前都已对源字体 `cmap` 校验过，转换器不会被要求凭空造字。
